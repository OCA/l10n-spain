This module generates a DeCA (electronic Control of Administration) PDF
for land carriage of goods from eligible Inventory transfers
(``stock.picking``). The report refers to Spanish Law 15/2009 on the
contract for the carriage of goods.

This Odoo 18 backport is based on the implementation proposed in
`OCA/l10n-spain#5281 <https://github.com/OCA/l10n-spain/pull/5281>`__
and the upstream source commit
``c10d5970feeffe1baf7cee6a2b0f6566698da7ed``.

The upstream proposal has not been merged. Its provenance does not
constitute OCA endorsement, maintenance, approval, or a legal-compliance
guarantee for this backport.

Scope:

- Outgoing transfers are eligible by default.
- Incoming transfers are eligible only when **Enable DeCA** is enabled
  on their operation type.
- Internal transfers are not eligible.
- Batch-transfer (``stock_picking_batch``) and purchase-order triggers
  are not provided.

Installation
============

Install this module in an Odoo 18 database with the ``stock`` module
available.

Configuration
=============

1. To make DeCA available for incoming transfers, go to **Inventory >
   Configuration > Operation Types**, open an incoming operation type,
   and enable **Enable DeCA**. This option is shown only for incoming
   operation types.
2. Ensure Inventory users (``stock.group_stock_user``) can work with the
   relevant transfers. The DeCA controls and report are restricted to
   this group.
3. Review the effective Odoo weight unit and product weights in your
   environment. The module does not validate those source values.
4. If the effective weight unit or a product's logistics unit changes
   later, stored DeCA weights are not recalculated automatically. Assess
   and selectively recompute affected ``deca_weight`` values.

The module computes DeCA weights during installation for existing stock
moves and pickings. It uses the done quantity when non-zero, otherwise
the planned quantity, excludes cancelled moves, and stores the result in
kilograms without rounding before display (up to Odoo's native
precision, six decimal places). Invalid effective weight units, or
positive weights too small to display at six decimals, prevent DeCA
issuance but do not block stock operations.

Security and sharing
--------------------

The **Share DeCA** link and QR code contain a bearer token. Anyone with
the link can download the PDF while the source transfer exists. Use the
button-provided link only through authorized channels. Copied transfers
and backorders receive a new token.

For a QR code to work outside the internal network, deploy Odoo over
HTTPS and configure an accessible ``web.base.url`` for the scanning
devices. Invalid, missing, or unrelated tokens return a generic
not-found response; the controller does not serve an older PDF as the
current one.

Storage and deletion
--------------------

Issued PDFs cannot be edited or directly deleted while their source
transfer exists. Deleting the source transfer also removes its DeCA
PDFs, so this is not a retention guarantee. The module does not define
retention periods or write-once storage, and does not provide a
legal-retention or legal-compliance guarantee.

Generic operations that directly write the protected issued attachment
may fail. In particular, use **Share DeCA** rather than generating a
separate public token for the attachment itself. Attachment-storage
migrations should be assessed before execution.

Usage
=====

1. Open an outgoing transfer, or an incoming transfer whose operation
   type has **Enable DeCA** enabled, from **Inventory > Operations >
   Transfers**.
2. In the **DeCA** tab, enter the required **Main vehicle or tractor
   licence plate** and **Carrier contact** (with VAT/NIF). The trailer
   plate and special traffic authorizations are optional.
3. Check the required sender, consignee, carrier, and weight data. For
   outgoing transfers, the sender is the warehouse contact (or company)
   and the consignee is the transfer contact; incoming transfers invert
   this direction.
4. Click **Print DeCA** to generate the PDF. Missing required data is
   reported by name.
5. Click **Share DeCA** and confirm the warning to open a link to the
   current PDF. A QR code for that link is included in the report.
6. If printed data changes, print or open the share link again to create
   a new version. Earlier versions remain attached to the transfer while
   it exists; the current version is shown by **DeCA Version**.

The PDF is generated when printed or when a valid share link is opened;
it is not emitted as a separate workflow step or frozen automatically
when the transfer is completed. If printed data is unchanged, the
current PDF is reused. After completion, changes to the main vehicle
plate, trailer plate, and special authorizations retain the previous
values, which are shown struck through in later versions.
