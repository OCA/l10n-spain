Delivery Transaher

This module integrates Odoo’s delivery framework with Grupo Transaher’s official SOAP Web Services (https://clientes.transaher.es), relying natively on OCA standard logistics modules (delivery_package_number, delivery_state, and stock_picking_volume):

  • Standard OCA Logistics Integration:
    • Package Count (``delivery_package_number``): Uses picking.number_of_packages for Datosentrada Field 11 (Bultos), 24-digit package barcode generation, QWeb labels, manifests, and per_package tariff rules.
    • Shipment Volume (``stock_picking_volume``): Uses picking.volume and product._get_volume_for_qty() for Datosentrada Field 13 (Volumen in m³) and volumetric chargeable weight calculation.
    • Carrier Tracking State (``delivery_state``): Implements transaher_tracking_state_update() for picking.tracking_state_update() and OCA’s scheduled cron _update_delivery_state(), populating delivery_state, tracking_state, tracking_state_history, tracking_json, date_shipped, and date_delivered.
  • Shipment Registration & Cancellation (``stock.picking``):
    • Automatic or manual shipment registration via awsprcsatsoap (wsPrcSATSOAP.Execute, Ediprocod = 20) building the 18-field pipe-separated Datosentrada string with comma decimal formatting and automatic pipe sanitization.
    • Full persistence of Transaher’s composite shipment identifier (Holding.Seccion.Centro.CodExpedicion) plus destination routing metadata (Centro_Destino, Area_Dis_Cod, Area_Dis_Dsc, Servicio, Expedicion_Ch).
    • One-click shipment cancellation via awsExpBaja (wsExpBaja.Execute) enforcing Transaher’s status rules (shipping_recorded_in_carrier).
  • Official & Local Standard Label Generation (PDF / ZPL / QWeb):
    • Automatic 20-minute token management via wsgetToken with cached reuse and transparent renewal on token expiration codes (1 / 2).
    • Official label download via wsEtiExpSOAP supporting Base64 PDF and thermal formats, configurable <Bultos> tag (-1 vs empty), and PosicionInicialImpresion for multi-label A4 sheets.
    • Built-in QWeb PDF 100x150mm 9-zone + 24-digit Code128 standard label generator implementing Transaher’s exact specification (including Portugal’s 4-digit postal code + 9 padding rule), usable standalone or as an automatic fallback.
  • Live Tracking, Incidences & Invoice Cost Auditing:
    • Direct link to Transaher’s web tracking portal.
    • Real-time synchronization via wsInformacionTransporte retrieving expedition events, incidences, deliveries, package SSCCs, and invoiced freight amounts (sdtImportes), auditing cost deviations (transaher_cost_difference).
  • Daily Loading Manifest (``awsmnfprtsoap``):
    • Interactive wizard querying awsmnfprtsoap (wsMnfPrtSOAP.Execute) for a date/time window (aaaammddhhmm) and generating a formatted PDF Loading Manifest (Manifiesto de Carga) for the driver’s signature.
  • Freight Tariff Engine & Internal Cost Preservation:
    • Configurable zone/province/postal-prefix/weight/package tariff rules (transaher.tariff.rule) supporting fixed, per_kg, per_excess_kg, per_100kg, and per_package calculation modes plus volumetric weight conversion and fuel, COD, and cargo insurance surcharges.
    • Internal estimated cost tracking on sale.order and stock.picking even when shipping is free for the customer.

Use Cases / Context

Companies shipping parcels and pallets across Spain and Portugal through Grupo Transaher need direct integration between Odoo’s sales and warehouse workflows and Transaher’s official SOAP Web Services (MTRANS_WEB / MWSBridge), eliminating manual shipment entry while automating 24-digit barcode labels, live tracking and incidence monitoring, daily loading manifests, and freight cost deviation auditing.

Installation

This module depends on the following OCA addons:

  • delivery_package_number (OCA/delivery-carrier)
  • delivery_state (OCA/delivery-carrier)
  • stock_picking_volume (OCA/stock-logistics-warehouse, which requires product_dimension from OCA/product-attribute)

Install delivery_transaher from the Odoo Apps menu or via command line:

odoo-bin -d <database> -i delivery_transaher

Configuration

To configure this module:

  1. Go to Inventory > Configuration > Delivery > Shipping Methods (or Sales > Configuration > Shipping Methods).
  2. Open the preconfigured Transaher Smart Logistic shipping method or create a new one with Provider = Transaher.
  3. In the Transaher Web Service Configuration tab:
    • Enter your Test Client Code (``CodigoCliente``), Test Password (``PasswordCliente``), Production Client Code (``CodigoCliente``), and Production Password (``PasswordCliente``) provided by Grupo Transaher.
    • Verify the Holding Code (0), Section Code (10), Origin Center Code (e.g. 461 for Valencia or 81 for Barcelona), Protocol Code (20), and Default Freight Terms (``Tipo de Portes``) (1 Freight Prepaid / 2 Freight Collect).
    • Select your Label Generation Mode (Transaher Web Service PDF (with Local QWeb Label Fallback), Transaher Web Service Only (wsEtiExpSOAP), or Local Standard Transaher Label PDF (24-digit Barcode)), wsEtiExpSOAP Package Tag (``<Bultos>``), and Initial Print Position (Multi-Label Sheet).
    • Click the Test Token wsgetToken smart button to validate authentication against wsgetToken.svc.
  4. In the Transaher Tariffs & Costs tab:
    • Configure Volumetric Factor (kg / m³) (e.g. 250), fuel, COD, and insurance surcharges, Free Shipping for Customer (Keep Internal Cost), and local zone/province/ZIP/weight/package tariff rules.

Usage

Calculating Shipping Rates on Sales Orders

  1. Create or open a Sales Order and click Add shipping.
  2. Select Transaher Smart Logistic and click Get rate.
  3. The wizard computes gross and volumetric weight (using OCA stock_picking_volume) and displays the Internal Transaher Cost (€), Chargeable Weight (kg), and a detailed Transaher Tariff Breakdown.
  4. Click Add to apply the shipping line and store the internal estimated cost on the order.

Sending Shipments & Printing Labels from Pickings

  1. Set Number of Packages (number_of_packages from delivery_package_number) or pack lines into physical packages; volume is computed automatically by stock_picking_volume.
  2. Validate the outgoing Delivery Order (stock.picking) or click Send to Shipper.
  3. Odoo registers the expedition in Transaher via awsprcsatsoap, sets delivery_state (shipping_recorded_in_carrier) and date_shipped (delivery_state), stores the composite reference (Holding.Seccion.Centro.CodExpedicion) and destination routing info, assigns 24-digit Transaher barcodes to packages, and attaches the shipping label in the chatter.
  4. In the Additional Info and Transaher Logistics tabs of the picking, you can:
    • Configure freight terms (Portes), postal repetition code, observations (Observaciones 1 & 2), insured value, or COD (Contra reembolso) prior to sending.
    • Click Transaher Label (WS) to reprint official labels via wsEtiExpSOAP or Print Standard Barcode Label (QWeb) to print the local 100x150mm 24-digit barcode label.
    • Click Update tracking state (tracking_state_update from delivery_state) or Update Tracking & Invoiced Costs to fetch live statuses, events, incidences, package SSCCs, and invoiced freight costs via wsInformacionTransporte (also updated automatically by delivery_state’s scheduled action).

Generating the Daily Loading Manifest

  1. Open the Transaher shipping method and click the Daily Manifest smart button (or navigate to Inventory > Reporting > Transaher Daily Manifest).
  2. Select the Date From and Date To range and click Query & Generate PDF Manifest or Print PDF Directly.

Known issues / Roadmap

  • Add dangerous goods (ADR) item declarations if exposed in future Transaher SOAP schema revisions.
  • Support automated Proof of Delivery (POD) image retrieval once enabled on wsInformacionTransporte.
